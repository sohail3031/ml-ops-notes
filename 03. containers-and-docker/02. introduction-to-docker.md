# What Is Docker?

When delivering an application to users, you may encounter problems caused by differences between environments, such as:

- Operating systems    
- System configurations
- External libraries
- Dependencies
- Infrastructure setups

**Docker** is a platform for building, packaging, distributing, and running applications using **containers**. It helps create consistent and isolated environments, making applications easier to develop, test, and deploy.

Docker packages an application and its dependencies so that the application can run consistently across different environments.

> [!NOTE]  
> Docker uses **containerization**, which is a form of OS-level virtualization. It is different from traditional hardware virtualization used by virtual machines.

---

## How Docker Works

Docker allows multiple isolated containers to run on the same host system.

Containers:

- Isolate application processes from one another.
- Package applications with their dependencies.
- Share the underlying host kernel when running natively on Linux.
- Use images as templates for creating containers.

A simplified view of Docker running on Linux is:

```text
┌──────────────────────────────────┐
│         Docker Containers        │
│                                  │
│  ┌──────────┐    ┌──────────┐    │
│  │ App A    │    │ App B    │    │
│  │ + Deps   │    │ + Deps   │    │
│  └──────────┘    └──────────┘    │
├──────────────────────────────────┤
│        Docker Engine             │
├──────────────────────────────────┤
│        Linux Operating System    │
├──────────────────────────────────┤
│            Hardware              │
└──────────────────────────────────┘
```

> [!IMPORTANT]  
> A container does **not** normally contain a complete independent operating system with its own kernel. Linux containers share the host's Linux kernel.

This makes containers generally more lightweight than traditional virtual machines.

## Docker Images and Containers

Docker primarily works with **images** and **containers**.

### Docker Image

A **Docker image** is a packaged, read-only template used to create containers.

An image can contain:

- Application code
- Libraries
- Dependencies
- Runtime environments
- Configuration
- System tools

Docker images are typically built using a **Dockerfile** or downloaded from a container registry.

### Docker Container

A **Docker container** is a running instance created from a Docker image.

A simplified relationship is:

```text
Dockerfile
    │
    ▼
Docker Image
    │
    ▼
Docker Container
```

A container adds a writable layer on top of the image layers while it is running.

> [!TIP]  
> A useful analogy is:
> 
> - **Dockerfile** → Instructions for building
>     
> - **Docker Image** → Template or blueprint
>     
> - **Docker Container** → Running instance
>

# Docker Architecture

Docker uses a **client-server architecture**.

The main components include:

1. Docker Client
2. Docker Daemon
3. Docker Objects
4. Docker Registry

```text
Docker Client
     │
     │ Docker API / Commands
     ▼
Docker Daemon
     │
     ├── Images
     ├── Containers
     ├── Networks
     └── Volumes
     │
     ▼
Docker Registry
```

---

## Docker Client

The **Docker client** is the primary interface used to interact with Docker.

It commonly provides a command-line interface (CLI) that allows you to perform operations such as:

- Building images
- Running containers
- Stopping containers
- Removing containers
- Downloading images
- Uploading images

For example:

```bash
docker run hello-world
```

The Docker client sends requests to the Docker daemon, which performs the requested operations.

A Docker client can communicate with one or more Docker daemons.

---

## Docker Daemon

The **Docker daemon** is a background service responsible for managing Docker resources.

It handles operations involving:

- Images
- Containers
- Networks
- Volumes

When you execute a Docker command, the Docker client communicates with the Docker daemon, which performs the required action.

### Docker on Different Operating Systems

On **Linux**, Docker can run directly on the host operating system because Linux containers use Linux kernel features.

On **Windows and macOS**, Linux containers typically require a Linux environment. Docker Desktop commonly uses a lightweight virtual machine to provide the Linux kernel required for running Linux containers.

```text
Windows/macOS Host
        │
        ▼
Docker Desktop
        │
        ▼
Lightweight Linux VM
        │
        ▼
Docker Engine
        │
        ▼
Linux Containers
```

# Docker Registry

A **Docker registry** is a service used to store and distribute container images.

A registry contains one or more **repositories**, and repositories contain one or more versions of container images.

```text
Docker Registry
│
├── Repository: python
│   ├── Image: python:3.12
│   ├── Image: python:3.11
│   └── Image: python:3.10
│
└── Repository: my-application
    ├── Image: v1.0
    └── Image: v2.0
```

A well-known public registry is **Docker Hub**.

Docker registries can also be private, allowing organizations to store and distribute internal container images.

Common registry operations include:

```text
Pull → Download an image

Push → Upload an image
```

# Docker Objects

Docker manages several types of objects.

Some important Docker objects include:

- Images
- Containers
- Networks
- Volumes

## Images

Images provide the template used to create containers.

Docker images commonly use a **layered filesystem**, allowing layers to be reused between images.

For example:

```text
Application Layer
────────────────────
Python Dependencies
────────────────────
Python Runtime
────────────────────
Base Operating System
```

Layer reuse helps improve storage efficiency and can speed up image builds and downloads.

## Containers

Containers are isolated runtime environments created from Docker images.

Multiple containers can be created from the same image.

```text
        Docker Image
             │
      ┌──────┼──────┐
      ▼      ▼      ▼
Container  Container  Container
    1          2          3
```

## Networks

Docker networks allow containers to communicate with:

- Other containers
- The host machine
- External networks

Docker provides networking capabilities that help isolate and connect containerized applications.

## Volumes

**Volumes** provide persistent storage for containers.

Containers themselves can be temporary, so volumes allow important data to persist independently of the container lifecycle.

# Dockerfile

A **Dockerfile** is a text file containing instructions used to build a Docker image.

A simplified example is:

```dockerfile
FROM python:3.12

WORKDIR /app

COPY . .

CMD ["python", "main.py"]
```

A Dockerfile can specify:

- A base image
- Working directories
- Files to copy
- Dependencies to install
- Environment configuration
- Commands to run

The Dockerfile is then used to build a Docker image.

```text
Dockerfile
    │
    ▼
docker build
    │
    ▼
Docker Image
```

# Advantages of Docker

## Consistent Environments

Docker helps ensure that an application runs in a consistent environment across different stages.

```text
Development
     │
     ▼
Testing
     │
     ▼
CI/CD
     │
     ▼
Production

Using the same or reproducibly built container image
```

This reduces environment-related issues.

## Simplified Deployment

Applications and their dependencies can be packaged into images and deployed without manually configuring every dependency on the target system.

## Portability

Containerized applications can be deployed across different environments, including:

- Local machines
- Development servers
- CI/CD environments
- Cloud platforms
- Kubernetes clusters

## Scalability

Multiple containers can be created from the same image, making it easier to scale applications.

For large-scale workloads, container orchestration platforms such as Kubernetes can manage multiple containers across multiple machines.

## Large Ecosystem and Community

Docker has a large ecosystem, extensive documentation, and a large developer community.

This makes it easier to find:

- Prebuilt images
- Documentation
- Tutorials
- Community support

# Limitations and Challenges

Docker also has some limitations.

## Dockerfile Knowledge

To build custom images effectively, you need to learn how to write and optimize Dockerfiles.

## Container Orchestration

Managing a small number of containers can be relatively straightforward. Managing hundreds or thousands of containers requires additional orchestration tools such as Kubernetes.

## Performance Overhead

Containers usually have lower overhead than virtual machines, but there can still be overhead compared with running an application directly on the host operating system.

This can be more noticeable in non-native environments, such as running Linux containers through virtualization on Windows or macOS.

## Security and Configuration

Containers are not automatically secure simply because they are isolated.

Proper practices are still required, including:

- Using trusted base images
- Keeping images updated
- Running containers with minimal privileges
- Managing secrets securely
- Limiting resource usage
- Scanning images for vulnerabilities

# Docker and MLOps

Docker is particularly important in **MLOps** because machine learning applications often have complex and specific dependencies.

For example, an ML application might require:

- A particular Python version
- Specific versions of ML libraries
- System dependencies
- GPU-related libraries
- Model-serving frameworks
- API dependencies

Docker can package these dependencies into a reproducible environment.

A simplified MLOps workflow may look like this:

```text
Develop Application
        │
        ▼
Create Dockerfile
        │
        ▼
Build Docker Image
        │
        ▼
Test the Container
        │
        ▼
Push Image to Registry
        │
        ▼
Deploy to Cloud / Kubernetes
        │
        ▼
Monitor Application
```

This makes Docker an important technology for building reproducible and deployable machine learning systems.

# Key Takeaways

- **Docker** is a platform for building, packaging, and running containerized applications.
- Docker uses a **client-server architecture**.
- The **Docker client** communicates with the **Docker daemon**.
- Docker manages objects such as **images, containers, networks, and volumes**.
- A **Docker image** is a template used to create containers.
- A **Docker container** is a running instance of an image.
- A **Dockerfile** contains instructions for building a Docker image.
- A **Docker registry** stores and distributes Docker images.
- Docker helps provide consistent and reproducible environments.
- Docker is widely used in **CI/CD, cloud computing, Kubernetes, and MLOps**.
