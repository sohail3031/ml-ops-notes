In this topic, you will take your first step toward understanding the fundamentals of Docker containers. You will learn how to create a simple `Dockerfile`, build a Docker image, find and inspect images, and understand image names, repositories, and tags.

By the end of this topic, you will know how to name and tag Docker images, as well as update the tags of existing images.

## Creating a Simple Dockerfile

To launch a container, you need a Docker image. Similarly, if you want to launch a customized container, you need to create a custom image.

A `Dockerfile` is a text file that contains instructions describing how to build a Docker image.

To create a `Dockerfile`:

1. Open any text editor.    
2. Create a new file.
3. Add the following instructions.
4. Save the file with the exact name `Dockerfile`, without a file extension.

The following `Dockerfile` creates a simple image based on **Ubuntu 22.04**:

```dockerfile
FROM ubuntu:22.04

LABEL author=HyperUser

ENTRYPOINT ["/bin/bash"]
```

The first instruction specifies the base image and version to use when building the image.

The remaining instructions may not be immediately clear:

- `LABEL` adds metadata to the image.
- `ENTRYPOINT` specifies the default executable that runs when a container starts.

These instructions will be explored in more detail later.

Once the `Dockerfile` is created, you can build an image from it and then use that image to create and run a container.

## Building a Docker Image

Once you have created a `Dockerfile`, you can use the `docker build` command to create an image from it.

The simplest command is:

```bash
docker build .
```

The `.` represents the **build context**.

The build context is the set of files and directories that Docker makes available to the build process. In this case, the `.` tells Docker to use the current working directory as the build context.

Docker will look for the `Dockerfile` in the current directory.

You can also explicitly specify the location of a `Dockerfile` using the `-f` flag:

```bash
docker build -f /path/to/my/Dockerfile .
```

Here:

- `-f /path/to/my/Dockerfile` specifies the location of the `Dockerfile`.
- `.` specifies the build context.

### Build Process

If this is the first time you are building an image using a particular base image, Docker may need to download the required image layers.

If the base image already exists locally, Docker can reuse it instead of downloading it again.

A successful build may produce output similar to the following:

```text
Sending build context to Docker daemon   12.8kB
Step 1/3 : FROM ubuntu:22.04
22.04: Pulling from library/ubuntu
5887826a0d8b: Pull complete
Digest: sha256:898852f07de8ff57e7810a5c28553e71f10db60ae79c2b7a06acc45bbb03741a
Status: Downloaded newer image for ubuntu:22.04
 ---> 2793294e6a90
Step 2/3 : LABEL author=HyperUser
Removing intermediate container 68bafd1194fb
 ---> 4f0e66ff57d5
Step 3/3 : ENTRYPOINT ["/bin/bash"]
Removing intermediate container 9baebdc3a08a
 ---> 97ac6dc27e4f
Successfully built 97ac6dc27e4f
```

The build process contains three steps, corresponding to the three instructions in the `Dockerfile`:

1. `FROM ubuntu:22.04`
2. `LABEL author=HyperUser`
3. `ENTRYPOINT ["/bin/bash"]`

The final line:

```text
Successfully built 97ac6dc27e4f
```

indicates that Docker successfully created the image.

The value `97ac6dc27e4f` is the resulting **image ID**.

## Exploring Docker Images

Docker provides commands for listing the images available on your system.

Use the following command:

```bash
docker images
```

The output may look similar to this:

```text
REPOSITORY   TAG       IMAGE ID       CREATED          SIZE
<none>       <none>    97ac6dc27e4f   28 seconds ago   70.2MB
ubuntu       22.04     63f3a805b672   6 days ago       126MB
```

The output contains the following important columns:

- **REPOSITORY** — The repository name of the image.
- **TAG** — The version or label associated with the image.
- **IMAGE ID** — The unique identifier of the image.
- **CREATED** — When the image was created.
- **SIZE** — The size of the image.

### Why Does the Image Show `<none>`?

The first image shows `<none>` under both the `REPOSITORY` and `TAG` columns because no name or tag was specified when the image was built.

An image without a repository or tag is commonly referred to as a **dangling image**.

### Why Are There Two Images?

Although you created only one custom image, Docker displays two images:

1. Your newly created image.
2. The official `ubuntu:22.04` base image used to build your custom image.

The `FROM ubuntu:22.04` instruction caused Docker to use the Ubuntu image as the base for your custom image.

## Docker Image Names

A Docker image name usually consists of two main components:

- **Repository** — A collection or location used to organize related versions of an image.
- **Tag** — A label that identifies a specific version or variant of an image.

The general format is:

```text
repository:tag
```

For example:

```text
ubuntu:v1
```

Where:

- `ubuntu` is the repository.
- `v1` is the tag.

An image name can also include additional components, such as a username or registry hostname. These are commonly used when working with container registries such as Docker Hub or private registries.

## Specifying an Image Name

To assign a name to an image while building it, use the `-t` flag.

The general syntax is:

```bash
docker build -t <repository>:<tag> .
```

For example, to create an image with:

- Repository: `ubuntu`
- Tag: `v1`

Run:

```bash
docker build -t ubuntu:v1 .
```

You can then check the available images with:

```bash
docker images
```

Example output:

```text
REPOSITORY   TAG       IMAGE ID       CREATED          SIZE
ubuntu       22.04     d50d2365accc   4 seconds ago    127MB
ubuntu       v1        c47d2c2e680e   3 minutes ago    127MB
```

### Viewing All Images

The regular `docker images` command does not always show every image, including certain untagged or intermediate images.

To display all images, use:

```bash
docker images -a
```

## Default `latest` Tag

If you specify a repository name but do not specify a tag, Docker automatically uses the `latest` tag.

For example:

```bash
docker build -t ubuntu .
```

is equivalent to building an image with:

```text
ubuntu:latest
```

Example output:

```text
REPOSITORY   TAG       IMAGE ID       CREATED          SIZE
ubuntu       latest    7009d4503cec   16 seconds ago   128MB
ubuntu       22.04     d50d2365accc   4 seconds ago    127MB
ubuntu       v1        c47d2c2e680e   3 minutes ago    127MB
```

> [!note]  
> `latest` is simply the default tag name. It does not necessarily mean that the image is the newest version.

## Assigning Multiple Tags

You can assign multiple tags to the same image during the build process.

For example:

```bash
docker build -t ubuntu:v1 -t ubuntu:latest .
```

This creates one image with two tags:

- `ubuntu:v1`
- `ubuntu:latest`

Multiple tags can point to the same underlying image.

## Tagging an Existing Image

You can also assign a new name or tag to an existing image.

The general syntax is:

```bash
docker image tag <image-id> <repository>:<tag>
```

For example, suppose an existing image has the ID:

```text
7009d4503cec
```

You can assign it the tag `ubuntu:v0` with:

```bash
docker image tag 7009d4503cec ubuntu:v0
```

After tagging the image, running:

```bash
docker images
```

may produce output similar to:

```text
REPOSITORY   TAG       IMAGE ID       CREATED          SIZE
ubuntu       latest    7009d4503cec   16 seconds ago   128MB
ubuntu       22.04     d50d2365accc   4 seconds ago    127MB
ubuntu       v1        c47d2c2e680e   3 minutes ago    127MB
ubuntu       v0        7009d4503cec   2 minutes ago    128MB
```

Notice that both `ubuntu:latest` and `ubuntu:v0` have the same image ID:

```text
7009d4503cec
```

This means they refer to the same underlying image.

> [!important]  
> Adding a new tag does not create a new copy of the image. Multiple tags can reference the same Docker image.

## Key Commands

|Command|Description|
|---|---|
|`docker build .`|Builds an image using the `Dockerfile` in the current directory.|
|`docker build -f <path> .`|Builds an image using a `Dockerfile` at a specified path.|
|`docker build -t <repository>:<tag> .`|Builds an image and assigns it a name and tag.|
|`docker images`|Lists Docker images.|
|`docker images -a`|Lists all images, including untagged and intermediate images.|
|`docker image tag <image-id> <repository>:<tag>`|Assigns a new tag to an existing image.|
