# Introduction to Kubernetes

Containerized applications have become a popular way to package and deploy software across different environments. Containers provide benefits such as portability, scalability, consistency, and efficient resource utilization.

However, managing a large number of containers across multiple machines can become complex. This is where **Kubernetes** helps.

## What Is Kubernetes?

**Kubernetes**, commonly abbreviated as **K8s**, is an open-source container orchestration platform used to deploy, manage, scale, and operate containerized applications.

Kubernetes provides features such as:

- Automated deployment
- Scaling
- Self-healing
- Load balancing
- Service discovery
- Resource management
- Storage orchestration
- Configuration and secret management

Kubernetes helps automate many operational tasks involved in running containerized applications across different environments.

> [!NOTE]  
> Kubernetes does not replace containers. Instead, it orchestrates and manages containerized workloads, typically across a cluster of machines.

## Brief History of Kubernetes

Kubernetes originated at **Google** and was released as an open-source project in **2014**.

Its design was influenced by Google's experience operating large-scale container management systems, particularly internal projects such as **Borg**.

Kubernetes was later donated to the **Cloud Native Computing Foundation (CNCF)**, where it is maintained and developed by a large open-source community.

Today, Kubernetes is one of the most widely used platforms for managing containerized applications in cloud and production environments.

# Core Kubernetes Concepts

Kubernetes manages resources through **objects**.

These objects describe the desired state of an application or infrastructure component and are typically defined using:

- YAML    
- JSON

For example, you might define a desired state such as:

```text
Run 3 replicas of an Nginx application.
```

Kubernetes continuously compares the desired state with the current state and uses control loops to attempt to reconcile any differences.

```text
Desired State
      │
      ▼
Kubernetes Control Loops
      │
      ▼
Actual State
      │
      └──── Differences Detected?
                │
          Yes ──┘
                │
                ▼
         Reconcile State
```

This **declarative approach** is one of the fundamental concepts of Kubernetes.

---

## Cluster

A **Kubernetes cluster** is a collection of machines that work together to run and manage containerized workloads.

A cluster typically consists of:

- A **control plane**    
- One or more **worker nodes**

```text
Kubernetes Cluster
│
├── Control Plane
│   ├── API Server
│   ├── Scheduler
│   ├── Controllers
│   └── etcd
│
└── Worker Nodes
    ├── Node 1
    ├── Node 2
    └── Node 3
```

---

## Node

A **Node** is a machine in a Kubernetes cluster that runs workloads.

A node can be:

- A physical machine    
- A virtual machine
- A cloud-based instance

Nodes provide resources such as:

- CPU
- Memory
- Storage
- Networking

Kubernetes schedules workloads onto available nodes.

---

## Pod

A **Pod** is the smallest deployable unit in Kubernetes.

A Pod can contain:

- One container    
- Multiple tightly coupled containers

Containers inside the same Pod typically share:

- Networking
- Storage volumes
- The Pod lifecycle

A simple example:

```text
Node
│
├── Pod
│   └── Application Container
│
└── Pod
    ├── Application Container
    └── Supporting Container
```

> [!IMPORTANT]  
> Kubernetes generally manages containers through Pods rather than deploying individual containers directly.

# Workload Resources

Kubernetes provides several workload objects for managing applications.

## Deployment

A **Deployment** manages stateless applications and declaratively controls the desired number of Pod replicas.

Deployments typically manage **ReplicaSets**, which in turn maintain the desired number of Pods.

```text
Deployment
     │
     ▼
ReplicaSet
     │
 ┌───┼───┐
 ▼   ▼   ▼
Pod Pod Pod
```

Deployments are commonly used for applications such as:

- Web applications    
- REST APIs
- Microservices

---

## ReplicaSet

A **ReplicaSet** maintains a specified number of identical Pod replicas.

For example:

```text
Desired Replicas: 3

Pod 1  ✓
Pod 2  ✓
Pod 3  ✓
```

If one Pod fails, the ReplicaSet attempts to create a replacement to restore the desired number of replicas.

ReplicaSets are commonly managed indirectly through Deployments.

---

## Job

A **Job** is used for tasks that are expected to run until completion.

Examples include:

- Database migrations    
- Batch processing
- Data processing
- One-time machine learning tasks

Once the task completes successfully, the Job is considered complete.

---

## CronJob

A **CronJob** creates Jobs on a scheduled basis.

Examples include:

- Daily backups    
- Scheduled data processing
- Periodic report generation
- Regular data cleanup

For example:

```text
Every day at 2:00 AM
         │
         ▼
      CronJob
         │
         ▼
        Job
         │
         ▼
    Task Executes
```

---

## DaemonSet

A **DaemonSet** ensures that a specified Pod runs on selected nodes, commonly one Pod per node.

DaemonSets are useful for node-level services such as:

- Logging agents    
- Monitoring agents
- Network services

```text
Node 1 → Monitoring Pod
Node 2 → Monitoring Pod
Node 3 → Monitoring Pod
```

---

## StatefulSet

A **StatefulSet** is designed for workloads that require stable identities or persistent storage.

It is commonly used for stateful applications such as:

- Databases    
- Distributed systems
- Message brokers

StatefulSets can provide:

- Stable Pod identities
- Ordered deployment and scaling
- Persistent storage association

---

# Labels and Selectors

Kubernetes objects can have **labels**, which are key-value pairs used to organize and identify resources.

For example:

```yaml
labels:
  app: web
  environment: production
```

Labels allow Kubernetes and users to select groups of related resources without depending on specific resource names or unique IDs.

For example, a Service can use a selector to target Pods with:

```text
app = web
```

Labels are an important mechanism for grouping and managing Kubernetes resources.

---

# Services

Pods can be created, replaced, and removed dynamically, so their IP addresses should not generally be treated as permanent endpoints.

A **Service** provides a stable way to access a group of Pods.

Services can help with:

- Service discovery    
- Load balancing
- Stable networking

```text
Users
   │
   ▼
Service
   │
┌──┼──┐
▼  ▼  ▼
Pod Pod Pod
```

The Service can route traffic to Pods that match its selector.

---

# Namespaces

**Namespaces** provide a way to logically group and isolate Kubernetes resources within a cluster.

They can be useful for separating environments or teams.

For example:

```text
Kubernetes Cluster
│
├── development
│   └── Application Resources
│
├── staging
│   └── Application Resources
│
└── production
    └── Application Resources
```

Namespaces help organize resources, although they are not intended to provide complete security isolation by themselves.

# Kubernetes Cluster Architecture

A Kubernetes cluster consists of two major parts:

1. **Control Plane**    
2. **Worker Nodes**

```text
                   Kubernetes Cluster
┌──────────────────────────────────────────────────┐
│                                                  │
│                 Control Plane                    │
│                                                  │
│  API Server ─ Scheduler ─ Controllers ─ etcd     │
│                       │                          │
├───────────────────────┼──────────────────────────┤
│                       │                          │
│            ┌──────────┴──────────┐               │
│            ▼                     ▼               │
│       Worker Node 1         Worker Node 2        │
│       ┌────────────┐        ┌────────────┐       │
│       │ kubelet    │        │ kubelet    │       │
│       │ kube-proxy │        │ kube-proxy │       │
│       │ Runtime    │        │ Runtime    │       │
│       │ Pods       │        │ Pods       │       │
│       └────────────┘        └────────────┘       │
│                                                  │
└──────────────────────────────────────────────────┘
```

# Control Plane Components

The **control plane** manages the overall state of the Kubernetes cluster.

## kube-apiserver

The **kube-apiserver** exposes the Kubernetes API.

It acts as the primary interface through which users and Kubernetes components communicate with the cluster.

Tools such as `kubectl` send requests to the API server.

```text
kubectl
   │
   ▼
API Server
   │
   ▼
Kubernetes Cluster
```

---

## kube-scheduler

The **kube-scheduler** is responsible for assigning unscheduled Pods to appropriate nodes.

It considers factors such as:

- Available resources    
- Scheduling constraints
- Node availability
- Pod requirements

---

## etcd

**etcd** is a distributed key-value store used by Kubernetes to store cluster state and configuration data.

It contains important information about the cluster's desired and current state.

> [!WARNING]  
> etcd contains critical cluster data and should be properly secured and backed up.

---

## kube-controller-manager

The **kube-controller-manager** runs Kubernetes controllers.

Controllers continuously monitor resources and work to move the actual state of the cluster toward the desired state.

Examples of controller responsibilities include:

- Maintaining the desired number of Pods    
- Managing nodes
- Managing Jobs
- Managing endpoints

---

## cloud-controller-manager

The **cloud-controller-manager** integrates Kubernetes with supported cloud providers.

It allows Kubernetes to interact with cloud infrastructure for resources such as:

- Load balancers    
- Storage
- Nodes
- Networking

This component is primarily relevant in cloud-based Kubernetes environments.

---

# Worker Node Components

Worker nodes provide the environment where Pods and containers run.

## kubelet

The **kubelet** is an agent that runs on each worker node.

It communicates with the Kubernetes control plane and works to ensure that the containers described in Pod specifications are running correctly.

---

## kube-proxy

**kube-proxy** helps implement network rules that enable communication with and between Kubernetes Services.

Depending on the configuration, it may use different mechanisms to implement service networking and traffic routing.

---

## Container Runtime

The **container runtime** is responsible for running and managing containers.

Kubernetes uses runtimes that implement the **Container Runtime Interface (CRI)**.

Common examples include:

- containerd    
- CRI-O

> [!NOTE]  
> Modern Kubernetes does not use the Docker Engine directly as its built-in container runtime. Docker images can still be used because common container image formats are supported by Kubernetes-compatible runtimes.

---

# Interacting with a Kubernetes Cluster

Kubernetes is primarily managed through its API.

Common ways to interact with a Kubernetes cluster include:

- `kubectl`    
- Web-based dashboards
- Kubernetes client libraries and SDKs
- Other tools built on the Kubernetes API

The most commonly used command-line tool is `kubectl`.

For example:

```bash
kubectl get pods
```

This command requests information about Pods from the Kubernetes API.

A typical interaction looks like:

```text
User
 │
 ▼
kubectl
 │
 ▼
Kubernetes API Server
 │
 ▼
Control Plane
 │
 ▼
Worker Nodes and Resources
```

# Benefits of Kubernetes

## Deployment Management

Kubernetes uses declarative configuration to manage application deployments.

You specify the desired state, such as:

```text
Desired replicas: 10
```

Kubernetes continuously works to maintain that state.

Kubernetes also supports deployment strategies such as:

- Rolling updates    
- Rollbacks
- Canary-style deployments through appropriate configurations and tooling
- Blue-green deployment patterns through appropriate configurations and tooling

---

## Self-Healing

Kubernetes can automatically respond to certain workload failures.

Depending on the workload configuration and health checks, Kubernetes can:

- Restart failed containers    
- Replace failed Pods
- Remove unhealthy endpoints from Service traffic
- Reschedule workloads when nodes fail

This reduces the amount of manual intervention required to maintain workloads.

---

## Storage Management

Kubernetes provides abstractions for managing persistent storage.

Depending on the environment, workloads can use:

- Local storage    
- Network storage
- Cloud provider storage

Storage can be provisioned and attached to workloads through Kubernetes storage resources.

---

## Extensibility

Kubernetes is highly extensible.

Additional functionality can be added through mechanisms such as:

- Add-ons    
- Custom Resource Definitions (CRDs)
- Operators
- Controllers

This extensibility allows Kubernetes to support a wide range of workloads and infrastructure environments.

---

## Configuration and Secrets

Kubernetes provides resources for managing application configuration and sensitive data.

Common resources include:

- **ConfigMaps** for non-sensitive configuration data    
- **Secrets** for sensitive configuration data

Examples include:

- Database credentials
- API keys
- OAuth tokens
- Application configuration

> [!WARNING]  
> Kubernetes Secrets should not automatically be considered fully encrypted at rest. Proper encryption-at-rest configuration, access controls, and secret-management practices are still important.

---

## Resource Efficiency

When defining workloads, you can specify resource requests and limits for resources such as:

- CPU    
- Memory

Kubernetes can use resource requests when scheduling workloads onto nodes.

For example:

```yaml
resources:
  requests:
    cpu: "500m"
    memory: "512Mi"

  limits:
    cpu: "1"
    memory: "1Gi"
```

This helps Kubernetes schedule workloads and manage cluster resources more effectively.

# Kubernetes in MLOps

Kubernetes is widely used in MLOps because machine learning platforms often consist of multiple distributed services.

For example:

```text
                 MLOps Platform
                      │
       ┌──────────────┼──────────────┐
       ▼              ▼              ▼
 Data Pipeline   Model Training   Model Serving
       │              │              │
       ▼              ▼              ▼
  Data Storage   GPU/CPU Jobs      API Services
       │              │              │
       └──────────────┼──────────────┘
                      ▼
                  Monitoring
```

Kubernetes can help manage:

- Model training jobs    
- Batch workloads
- Model-serving applications
- API services
- Data-processing pipelines
- Monitoring systems
- Resource allocation
- Automatic scaling

For example, model-serving Pods may scale based on demand, while training workloads can run as Jobs using specialized CPU or GPU resources.

This makes Kubernetes an important technology in many modern MLOps platforms.

# Key Takeaways

- **Kubernetes (K8s)** is an open-source platform for orchestrating containerized applications.    
- Kubernetes uses a **declarative model** where users describe the desired state of the system.
- A **Kubernetes cluster** consists of a control plane and one or more worker nodes.
- A **Node** is a machine that provides resources for running workloads.
- A **Pod** is the smallest deployable unit in Kubernetes and can contain one or more containers.
- **Deployments** commonly manage stateless applications and use ReplicaSets to maintain the desired number of Pods.
- **Jobs** and **CronJobs** are used for one-time and scheduled tasks.
- **DaemonSets** run Pods on selected nodes.
- **StatefulSets** are designed for workloads requiring stable identities or persistent storage.
- The control plane manages the overall state of the cluster.
- `kubelet`, `kube-proxy`, and a container runtime are important components of worker nodes.
- `kubectl` is a commonly used command-line tool for interacting with Kubernetes.
- Kubernetes provides capabilities such as automated deployment, scaling, self-healing, storage management, configuration management, and resource scheduling.
- Kubernetes is widely used in **cloud computing, DevOps, and MLOps**.
